# Hosted account and installation registry

The public platform is a directory, not the execution router. Its database must
be separate from user-owned router databases. It stores no LLM keys, task content,
workspace files, or user database connection strings.

## Run

Supply `DATABASE_URL` for an empty platform database, `PUBLIC_ORIGIN` for the exact
browser origin, and optionally `HOST`/`PORT` (defaults `127.0.0.1:8080`). Secrets
belong in the deployment's environment, not shell history or source control.

```sh
cargo run --locked -p cuttlefish-platform
```

The Dockerfile builds a non-root runtime. `railway.toml` configures the build,
`/healthz` readiness check, and bounded crash restarts. Migrations run on startup.
The Railway staging database serves this platform only.

## JSON API

All API paths begin with `/api/v1`. JSON requests have a 16 KiB body limit.
Lists use an optional exclusive UUID `after` cursor and return at most 100 records.
Continue after the last record when a full page is returned.

| Method | Path | Input / result |
| --- | --- | --- |
| GET | `/status` | Public service name, API version, configured origin |
| POST | `/auth/register` | `username`, `password`; creates account and session |
| POST | `/auth/login` | `username`, `password`; creates session |
| GET | `/auth/session` | Authenticated account ID |
| POST | `/auth/logout` | Revokes current session |
| GET | `/groups` | Current account's groups and installation counts |
| POST | `/groups` | `name`; returns `group_id` |
| GET | `/groups/{group}/installations` | Group's safe installation directory |
| POST | `/groups/{group}/invitations` | New single-use invitation, valid 30 minutes |
| POST | `/installations/preflight` | `group_id`, `invitation`; currently allowed roles and router origin |
| POST | `/installations` | Exact registration below; returns installation and router address |
| GET | `/installations/self` | Installation credential's own directory entry |
| POST | `/installations/heartbeat` | `ready`, optional router/agent dashboard URLs |
| POST | `/router/authorize-agent` | Router credential verifies an agent's `installation_id`, `credential` within its group |

Account passwords are Argon2id hashes. Sessions expire after eight hours. Browser
clients use HTTP-only SameSite=Strict cookies; HTTPS deployments also set Secure.
Native clients use the returned session token as a Bearer credential. Do not send
both cookie and Bearer authentication. Browser mutations require the configured
Origin. Bearer-only native requests can omit Origin. Login attempt reservations
are durable, shared across replicas, and limited to five per account per minute.
Password hashing has a bounded per-process worker admission limit.

Installation endpoints authenticate separately from account sessions. Group IDs
are identifiers, not credentials. Tokens are 64 lowercase hex characters; public
listings never return them. A rejected request does not consume an invitation.

## Registration and recovery

The installer must save this full request in local protected state before sending
it. Generate `installation_id` and `credential` once; never replace them merely
because an HTTP response was lost.

```json
{
  "group_id": "11111111-1111-4111-8111-111111111111",
  "installation_id": "22222222-2222-4222-8222-222222222222",
  "role": "router_agent",
  "name": "Primary server",
  "router_url": "https://router.example.com",
  "credential": "<64 lowercase hex characters generated by installer>",
  "invitation": "<one-use invitation from the signed-in group owner>"
}
```

Roles are `router_agent`, `router`, and `agent`. Agent-only registrations omit
`router_url` and require a fresh ready router. A unique partial index and group
row lock enforce one router per group. An offline router retains its identity.
Exact committed retries succeed even after the invitation expires; altered
retries are rejected. Heartbeat freshness is a directory indicator, never an
execution replay or failover permission.

The user-owned router must verify enrollment with `/router/authorize-agent`
before granting execution access. This API's existence does not automatically
wire the existing operator-only coordinator CLI to hosted enrollment.

## Scope and next integration

The account/group website and registry are implemented. The interactive installer,
automatic local database provisioning, hosted-to-local enrollment adapter, and
local router/agent administration dashboards are separate integration work.
A directory registration does not mean a runtime has been installed or started.
Readiness must only be advertised after the installed runtime is actually ready.
